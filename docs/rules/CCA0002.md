# CCA0002: Remove redundant type arguments

CCA0002 reports the type argument list of a generic method call when type inference supplies the same type arguments, and its code fix removes the list.

The rule runs in `dotnet build` and in the IDE.

## Descriptor

| Property         | Value                                                                                                        |
| ---------------- | ------------------------------------------------------------------------------------------------------------ |
| ID               | CCA0002                                                                                                      |
| Title            | Remove redundant type arguments                                                                              |
| Message          | `Call can be simplified by removing '{0}'`, where `{0}` is the type argument list's text, such as `<string>` |
| Category         | Style                                                                                                        |
| Default severity | Info, enabled by default                                                                                     |
| Custom tags      | Unnecessary                                                                                                  |
| Help link        | <https://github.com/ChilliCream/analyzer-config/blob/main/docs/rules/CCA0002.md>                             |

## What the rule reports

The rule reports a type argument list only when every type argument qualifies and the call without the list binds the same way. When the result is uncertain, it reports nothing. Generated code is not analyzed.

The examples assume `using System.Linq;` and `using System.Threading.Tasks;`, a method `static T Id<T>(T value) => value;`, and a `numbers` variable of type `List<int>`.

```csharp
// before
var task = Task.FromResult<string>("x");
var first = numbers.First<int>();
var texts = numbers.Select<int, string>(x => x.ToString());

// after
var task = Task.FromResult("x");
var first = numbers.First();
var texts = numbers.Select(x => x.ToString());
```

The rule reports a call through a simple name (`Id<int>(x)`), a member access (`numbers.First<int>()`), and a conditional access (`items?.First<int>()`, where `items` is a `List<int>?`). It checks calls in statements, top-level statements, local functions, lambdas, anonymous methods, field and property initializers, expression-bodied members and accessors, constructor initializers, and primary constructor base types.

### Qualifying type arguments

Every type argument in the list must qualify, at every depth:

| Type argument                                | Qualifies | Why                                                                                                       |
| -------------------------------------------- | --------- | --------------------------------------------------------------------------------------------------------- |
| Value types                                  | Yes       | `int`, `int?`, `Guid`, an enum, a record struct, `ValueTask<int>`, `ImmutableArray<int>`                  |
| Sealed classes                               | Yes       | `string`, `string?`, a sealed class or record. A `?` annotation does not affect whether it qualifies      |
| Delegates                                    | Yes       | `Action`, `Func<string, int>`                                                                             |
| Arrays and tuples                            | Yes       | `string[]`, `int[,]`, `(string Name, int Age)`, when the element types qualify                            |
| Abstractions                                 | No        | An interface, an abstract class, or a class that is not sealed (`List<int>`, `Task<int>`)                 |
| `object` and `dynamic`                       | No        | Neither is a sealed class or a value type                                                                 |
| Nested abstractions                          | No        | `Func<IWidget>`, `IWidget[]`, `(string, IWidget)`, `KeyValuePair<string, object>`, `Outer<IWidget>.Inner` |
| Type parameters with `struct` or `unmanaged` | Yes       | They are value types                                                                                      |
| Other type parameters                        | No        | An unconstrained type parameter, or one constrained to `class`, `notnull`, or a base type                 |

A generic type qualifies when it is a value type, a sealed class, or a delegate, and every type argument of it and of its containing types qualifies.

### The binding check

The rule reports the list only when the call without it binds:

- To the same method.
- With the same type arguments, including nullable annotations and tuple element names.
- Without changing the type or the symbol of any enclosing expression, such as the call that receives a lambda around it.

The nullable flow state of each argument counts, so `Id<string?>(n)` for a `string?` parameter `n` that may be null is reported, and so is `Id<string>(n)` after `if (n is null) return;`. `Id<KeyValuePair<string, string?>>(pair)` is reported when `pair` has that exact type.

With `Apply<T>(T seed, Func<T, T> map)`, `Apply` infers `string` from `"x"` with or without the list, so the rule reports `<string>`:

```csharp
Apply("x", x => Id<string>(x));
```

## What the rule does not report

- Type arguments of a generic type, such as `new List<int>()`.
- A method group that is not invoked, such as `numbers.ForEach(Print<int>)` or `Func<int, int> map = Id<int>;`.
- Type arguments inside `nameof`, `typeof`, and attribute arguments.
- A list with a type argument that does not qualify, such as `Id<IWidget>(widget)`, even when inference gives the same type.
- A list whose removal makes inference give another type, such as `Id<long>(42)`, which infers `int`, or `Id<string?>(s)` for a `string` parameter `s`.
- A list whose removal drops tuple element names, such as `Id<(string Name, int Age)>(("x", 1))`.
- A list whose removal makes the call bind to another method, such as `M<int>(1)` beside a non-generic `M(int)`.
- A list whose removal leaves type arguments that cannot be inferred, such as `Id<string[]>(["x"])`.
- A list whose removal changes an enclosing call, such as `Use(x => Id<int>(x))` when `Use` has overloads that take a `Func<string, string>` and a `Func<int, int>`.
- A list whose removal, together with the other lists the rule reports in the same statement or initializer, would change a binding, such as each list in `Use(x => Id<int>(x), y => Id<int>(y))` when `Use` has overloads that take two `Func<string, string>` parameters and two `Func<int, int>` parameters.
- Any list in a statement or initializer with more than eight candidate type argument lists, such as a sum of nine `Id<int>(n)` calls.
- A call in a query clause other than the first `from` source, such as `Id<int>(x)` in `from x in items select Id<int>(x)`.
- A call in another position the rule does not compare, such as a collection expression element.
- A call in a generic local function's expression body whose type arguments use that function's type parameters, such as `Id<T>(value)` in `static T Wrap<T>(T value) where T : struct => Id<T>(value);`, or the recursive `Pick<T>(value, false)` in `static T Pick<T>(T value, bool again) where T : struct => again ? Pick<T>(value, false) : value;`.
- A reference type argument in a project that enables nullable annotations but no nullable warnings anywhere, such as one with `<Nullable>annotations</Nullable>`, because the compiler infers oblivious type arguments there. Value type arguments are still reported.
- In a project that enables nullable, a reference type argument in a `#nullable disable` region whose argument was declared where nullable is enabled, such as `Id<string>(s)` inside the region for a `string` parameter `s` declared outside it.
- A list with a comment or a preprocessor directive inside it.
- A call that does not bind to exactly one method without errors.

## Configuration

Set the severity in an `.editorconfig` or globalconfig file:

```ini
dotnet_diagnostic.CCA0002.severity = warning
```

`ChilliCream.AnalyzerConfig.Libraries` sets CCA0002 to `warning`. Use `none` to turn the rule off.

The code fix ships in `ChilliCream.Analyzers`. Fix All applies every diagnostic in one pass, and in each statement or initializer it removes only lists that were proven safe to remove together.

## Related rules

- [IDE0001] runs only in the IDE, because it is not among the code-style analyzers that `EnforceCodeStyleInBuild` adds to a build. `ChilliCream.AnalyzerConfig.Libraries` turns it off. CCA0002 reports a subset of the generic method type arguments that [IDE0001] removes: those whose types are sealed or value types and whose removal it can prove keeps the same method.
- [CCA0001] reports a qualified name whose shorter form binds to the same symbol. It does not report type arguments of a generic method.
