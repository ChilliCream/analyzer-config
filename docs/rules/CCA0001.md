# CCA0001: Simplify name

CCA0001 reports a qualified name whose shorter form binds to the same symbol, and its code fix removes the unneeded part.

The rule runs in `dotnet build` and in the IDE.

## Descriptor

| Property         | Value                                                                            |
| ---------------- | -------------------------------------------------------------------------------- |
| ID               | CCA0001                                                                          |
| Title            | Simplify name                                                                    |
| Message          | `Name can be simplified by removing '{0}'`, where `{0}` is the removed text      |
| Category         | Style                                                                            |
| Default severity | Info, enabled by default                                                         |
| Custom tags      | Unnecessary                                                                      |
| Help link        | <https://github.com/ChilliCream/analyzer-config/blob/main/docs/rules/CCA0001.md> |

## What the rule reports

The rule reports a name only when the shorter form binds to the same symbol as the original. When the result is uncertain, it reports nothing. Using directives are not analyzed.

The examples assume that the namespaces they name are imported with using directives.

### Namespace qualifier

The rule reports a namespace qualifier in type positions and in expressions, including a qualifier that starts with `global::` or goes through a namespace alias, such as `Text.StringBuilder` with both `using System.Text;` and `using Text = System.Text;`.

```csharp
// before
var info = new System.IO.FileInfo(path);
System.Console.WriteLine(info);

// after
var info = new FileInfo(path);
Console.WriteLine(info);
```

A containing type stays:

```csharp
// before
System.Collections.Generic.Dictionary<string, int>.KeyCollection keys;

// after
Dictionary<string, int>.KeyCollection keys;
```

### The `global::` alias

The rule reports `global::` alone when neither the simple name nor the name without its namespace binds to the same symbol. In the example, the code sits inside a namespace that declares its own `Record`, such as `App.Record` inside `namespace App`.

```csharp
// before
global::Vendor.Logs.Record record;

// after
Vendor.Logs.Record record;
```

### Nested-type qualifier

The rule reports the containing type of a nested type inside the containing type, inside a type derived from it, or when a `using static` directive imports it. In an expression, the kept name must be a type.

```csharp
// before
Outer.Inner inner;
Outer.Inner.Create();

// after
Inner inner;
Inner.Create();
```

### Attribute names

The rule reports the qualifier and the `Attribute` suffix as two diagnostics when each removal keeps the same constructor, so either fix is safe on its own.

```csharp
// before
[System.ObsoleteAttribute]

// after
[Obsolete]
```

### Documentation comment references

The rule reports namespace qualifiers, a redundant `global::`, and nested-type qualifiers in a cref's type, its container, and the types in its parameter list and conversion-operator return type.

```csharp
// before
/// <see cref="System.IO.File"/>

// after
/// <see cref="File"/>
```

A build checks crefs only in projects that generate a documentation file, so set `GenerateDocumentationFile` to `true` to have it report them. The IDE always checks them.

### Type arguments

A name inside a type argument list is reported on its own, and the diagnostics never overlap. A removal is skipped when it would contain a type argument that is reported on its own.

```csharp
// before
System.Collections.Generic.List<System.Text.StringBuilder> builders;

// after
List<StringBuilder> builders;
```

## What the rule does not report

- Part of a namespace, so `System.IO.FileInfo` never becomes `IO.FileInfo`.
- A name replaced with a using alias.
- A type qualifier on a static member access, such as `File.Exists(path)`.
- `this.` and `base.` qualifiers.
- Type arguments of a generic method.
- A static member access rewritten to the member's declaring type.
- `Nullable<T>` to `T?` and a framework type name to its keyword, which [RCS1020] and [RCS1013] cover. CCA0001 still removes the namespace from `System.Int32`.
- A name with a preprocessor directive or a comment inside the part that would be removed.
- A name that has an open generic type before its last part, such as `A.B<>.C`.
- An `alias::` qualifier other than `global::`, such as `Sys::Text.StringBuilder`.
- A cref type qualifier on a member reference, so `File.Exists(string)` stays.
- A name that does not bind to exactly one symbol without errors.

## Color Color

A simple name that matches a field, property, local, or parameter of the same type is a Color Color name, such as a `Color` property of type `Color`. The rule shortens a qualified type to such a name only when all of these hold:

- The name also binds as a type to the same type.
- The name is the receiver of a member access whose member is a field, property, event, or nested type, and not a method or an extension member.
- A local of that name and type counts only when it is declared before the name. A `foreach` loop variable counts inside its loop body, and a deconstruction variable does not count inside its own assignment.
- The shortened member access binds to the same member as the original.

```csharp
public Encoding Encoding { get; } = System.Text.Encoding.UTF8;
```

The rule reports `System.Text.` in the line above. It does not report `Paint.Color.M(1)`, a method call through a Color Color name.

## Configuration

Set the severity in an `.editorconfig` or globalconfig file:

```ini
dotnet_diagnostic.CCA0001.severity = warning
```

`ChilliCream.AnalyzerConfig.Libraries` sets CCA0001 to `warning`. Use `none` to turn the rule off.

The code fix ships in `ChilliCream.Analyzers`, and Fix All applies every diagnostic in one pass. A nested type whose removed qualifier contains a type argument that is reported on its own can need a second pass.

## Related rules

- [IDE0001] and [IDE0002] run only in the IDE, because they are not among the code-style analyzers that `EnforceCodeStyleInBuild` adds to a build. [IDE0001] also reports rewrites that CCA0001 leaves out. `ChilliCream.AnalyzerConfig.Libraries` turns them off in favor of CCA0001.
- [IDE0049] prefers language keywords over framework type names. `ChilliCream.AnalyzerConfig.Libraries` turns it off in favor of [RCS1013], "Use predefined type".
- [RCS1013] and [RCS1020] are Roslynator rules. [RCS1013] reports predefined types, and [RCS1020] ("Simplify `Nullable<T>` to `T?`") reports `Nullable<T>`. `ChilliCream.AnalyzerConfig.Libraries` sets both to `warning`.
