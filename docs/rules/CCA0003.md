# CCA0003: Access members through their declaring type

CCA0003 reports a type name that qualifies a static member or a nested type it only inherits, and its code fix writes the declaring type in its place.

The rule runs in `dotnet build` and in the IDE.

## Descriptor

| Property         | Value                                                                                                                           |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| ID               | CCA0003                                                                                                                         |
| Title            | Access members through their declaring type                                                                                     |
| Message          | `Access '{0}' through its declaring type '{1}'`, where `{0}` is the member's name and `{1}` the replacement, such as `Encoding` |
| Category         | Style                                                                                                                           |
| Default severity | Info, enabled by default                                                                                                        |
| Custom tags      | None                                                                                                                            |
| Help link        | <https://github.com/ChilliCream/analyzer-config/blob/main/docs/rules/CCA0003.md>                                                |

## What the rule reports

The rule reports a type name only when the declaring type can be named at that position and the code with the declaring type in its place binds to the same member, with nothing around it binding differently. When the result is uncertain, it reports nothing. Generated code is not analyzed.

The examples assume `using System;`, `using System.Text;`, and `using System.Threading.Tasks;`, and the types `Base`, `Derived`, and `Widget` declared as follows:

```csharp
public class Base
{
    public static Base Create() => new Base();

    public class Nested
    {
        public static void Run()
        {
        }
    }
}

public class Derived : Base
{
}

public class Widget
{
}
```

```csharp
// before
var encoding = UTF8Encoding.Default;
var delay = Task<int>.Delay(10);
var names = DayOfWeek.GetNames(typeof(DayOfWeek));
var created = Derived.Create();
var same = Widget.ReferenceEquals(created, created);
Derived.Nested.Run();

// after
var encoding = Encoding.Default;
var delay = Task.Delay(10);
var names = Enum.GetNames(typeof(DayOfWeek));
var created = Base.Create();
var same = object.ReferenceEquals(created, created);
Base.Nested.Run();
```

### Positions

| Position       | Example                                                                                                          | Becomes                           |
| -------------- | ---------------------------------------------------------------------------------------------------------------- | --------------------------------- |
| Member access  | A field, constant, property, event, or method, invoked or as a method group: `Derived.Create()`, `Derived.Parse` | `Base.Create()`, `Base.Parse`     |
| `nameof`       | `nameof(Derived.Default)`                                                                                        | `nameof(Base.Default)`            |
| Nested type    | `Derived.Nested.Run()` in an expression                                                                          | `Base.Nested.Run()`               |
| Type name      | `Derived.Nested` in a declaration, `typeof`, a cast, a pattern, a type argument, or a base list                  | `Base.Nested`                     |
| Cref type name | A type inside a cref, such as a parameter type: `<see cref="Take(Derived.Nested)"/>`                             | `<see cref="Take(Base.Nested)"/>` |

The qualifier can take any form that names a type: a simple name, a namespace-qualified or `global::` name, a generic name such as `Task<int>`, a keyword such as `string`, or a using alias. The rule reports and replaces the whole qualifier, so `System.Text.UTF8Encoding.Default` becomes `Encoding.Default` where `System.Text` is imported.

### Declaring types

The declaring type can be any type the qualifier inherits the member from:

- A base class at any depth.
- `object`, from any type.
- `System.Enum`, from an enum type.
- A base interface, from a derived interface.

A static member accessed inside the qualifier's own type is reported too: inside `Derived`, `Derived.Create()` becomes `Base.Create()`.

### Nested qualifiers

When one candidate qualifier contains another, the rule checks the outer one first. If it reports the outer one, it does not report the inner one. In `D.Inner.M()`, where `D` inherits `Inner` from `B` and `Inner` inherits `M` from `Base`, the rule reports `D.Inner`, and the fix writes `Base.M()`. If the rule does not report the outer qualifier, for example because `Base` is generic, it checks the inner one on its own, and `D` becomes `B`.

### Replacement forms

The fix writes the declaring type in the first of these forms that binds to it at the qualifier's position:

1. The keyword, for `object`.
2. The simple name, such as `Encoding`.
3. The name qualified by its containing types, such as `Outer.Base`.
4. The namespace-qualified name, such as `Foo.Testing.TestBase`.
5. The namespace-qualified name with `global::`.

In an expression, the form must bind as an expression, so a property named like the declaring type (Color Color) takes part as it does for [CCA0001]. If no form binds, the rule skips the access. The fix never writes a using alias or a namespace-relative name, and never adds a `using` directive.

### The binding check

For an access in an expression, the rule rewrites the qualifier and binds the result again. It reports the access only when all of these hold:

- The rewritten access binds to the same member.
- No enclosing expression changes its type or symbol, such as the call that receives a lambda around the access.
- The rewrite stays valid together with every other rewrite the rule reports in the same statement or initializer.

The examples use these declarations:

```csharp
class Base
{
    public static int M(int x) => x;
    public static int M(object o) => 0;
}

class Derived : Base
{
    public static string M(string s) => s;
}

static void Use(Func<int, int> map) { }
static void Use(Func<string, int> map) { }
static T Apply<T>(T seed, Func<T, T> map) => map(seed);
```

`Use(x => Derived.M(x))` binds `Base.M(int)`, and the rule reports nothing. With `Base.M` in place of `Derived.M`, the call to `Use` is ambiguous (CS0121), because the `string` overload of `Use` becomes applicable once `Derived.M(string)` is out of the method group.

`Apply(1, x => Derived.M(x))` keeps its overload and its binding with the rewrite, and the rule reports `Derived`:

```csharp
// before
Apply(1, x => Derived.M(x));

// after
Apply(1, x => Base.M(x));
```

A type name is reported once the replacement names the same type.

## What the rule does not report

- A type name that qualifies a member it declares itself, or one it hides with `new`.
- A generic declaring type, or one nested in a generic type, such as `MyComparer.Default` where `MyComparer` derives from `EqualityComparer<string>`.
- A declaring type marked `[EditorBrowsable(EditorBrowsableState.Never)]` or `[EditorBrowsable(EditorBrowsableState.Advanced)]`.
- Instance members, which a type name reaches only in `nameof`, such as `nameof(Derived.Name)`.
- Static extension members.
- A qualifier that is a type parameter, such as `T.Create()` for a static abstract member.
- The qualifier of a cref member reference, such as `Derived.Nested` in `<see cref="Derived.Nested.M"/>`. A type name inside a cref, such as a parameter type, is reported.
- Names in `using` directives.
- Attribute names, such as `[Derived.NestedAttribute]`.
- A `nameof` argument that names members with more than one declaring type, such as `nameof(Derived.M)` where `Derived` and `Base` both declare an `M`.
- An access whose rewrite changes the binding of an enclosing call, such as `Use(x => Derived.M(x))` above.
- Any access in a statement or initializer with more than eight candidates.
- A declaring type that no replacement form names, such as one in an assembly referenced only through an extern alias.
- A qualifier with a compile error, a preprocessor directive, or a comment inside it.
- A qualifier that [CCA0001] removes in full, while CCA0001 is enabled for the file. Inside `Base` or a type derived from it, CCA0001 reports `Derived.` in `Derived.Nested`, so CCA0003 does not report `Derived`. When CCA0001 removes only part of a qualifier, such as `System.Text.` in `System.Text.UTF8Encoding.Default`, both rules report, and either fix first leads to `Encoding.Default`.

CCA0001 is enabled for a file unless its severity is `none` in an `.editorconfig`, a global config, or the compilation options. When it is `none`, CCA0003 reports the qualifier itself, so `Derived.Nested` becomes `Base.Nested`. A `#pragma warning disable CCA0001` or a `[SuppressMessage]` for CCA0001 does not count as disabled, so CCA0003 stays silent there.

## Configuration

Set the severity in an `.editorconfig` or globalconfig file:

```ini
dotnet_diagnostic.CCA0003.severity = warning
```

`ChilliCream.AnalyzerConfig.Libraries` sets CCA0003 to `warning`. Use `none` to turn the rule off.

The code fix ships in `ChilliCream.Analyzers`. Fix All applies every diagnostic in one pass, because the reported qualifiers never overlap and the rewrites reported in one statement or initializer were proven safe together.

## Related rules

- [IDE0001] and [IDE0002] run only in the IDE, because they are not among the code-style analyzers that `EnforceCodeStyleInBuild` adds to a build. `ChilliCream.AnalyzerConfig.Libraries` turns them off. Roslyn reports the rewrite that CCA0003 reports as [IDE0002] in an expression and as [IDE0001] in a type name.
- [CCA0001] reports a qualified name whose shorter form binds to the same symbol. It never names a different type. CCA0003 leaves it a qualifier that it removes in full, and does so only while CCA0001 is enabled for the file.
