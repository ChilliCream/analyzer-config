# CCA0004: Remove 'this' qualification

CCA0004 reports `this.` in front of an instance field, property, method, or event that the name alone reaches, and its code fix removes it.

The rule runs in `dotnet build` and in the IDE.

## Descriptor

| Property         | Value                                                                                     |
| ---------------- | ----------------------------------------------------------------------------------------- |
| ID               | CCA0004                                                                                   |
| Title            | Remove 'this' qualification                                                               |
| Message          | `Access to '{0}' can be simplified by removing 'this.'`, where `{0}` is the member's name |
| Category         | Style                                                                                     |
| Default severity | Info, enabled by default                                                                  |
| Custom tags      | `Unnecessary`                                                                             |
| Help link        | <https://github.com/ChilliCream/analyzer-config/blob/main/docs/rules/CCA0004.md>          |

The code fix is titled `Remove 'this' qualification`.

## What the rule reports

The rule reports `this.X` only when the name alone reaches the same member, nothing around the access binds differently without `this.`, the code parses the same way, and every removal the rule reports in the same statement or initializer holds together. When the result is uncertain, it reports nothing. Generated code is not analyzed.

The example assumes `using System;`.

```csharp
public sealed class Counter(int start)
{
    private int _count = start;

    public event EventHandler? Changed;

    public int Count => this._count;

    public void Add(int count) => this._count += count;

    public void Raise()
    {
        this.Changed?.Invoke(this, EventArgs.Empty);
    }
}
```

The rule reports `this.` in `this._count` and in `this.Changed`. The `this` argument stays. The code fix leaves this:

```csharp
public sealed class Counter(int start)
{
    private int _count = start;

    public event EventHandler? Changed;

    public int Count => _count;

    public void Add(int count) => _count += count;

    public void Raise()
    {
        Changed?.Invoke(this, EventArgs.Empty);
    }
}
```

The diagnostic covers `this` through the `.`, and the fix deletes exactly that span.

The fix changes the text that a `[CallerArgumentExpression]` parameter captures. After the fix, `ArgumentNullException.ThrowIfNull(this._s)` reads `ArgumentNullException.ThrowIfNull(_s)`, and the `ParamName` of the exception it throws changes from `this._s` to `_s`.

### Positions

The rule reports `this.X` where `X` is an instance field, property, method, or event, in any of these positions:

- Read, written, or invoked, including a generic method (`this.M<int>()`).
- A method group converted to a delegate.
- An event that is invoked or subscribed to (`this.Changed += Handler`).
- `nameof(this.X)`.
- An object-initializer value.
- An anonymous-type or tuple element (`new { this.X }`, `(this.a, this.b)`), where the inferred name stays `X`.
- An interpolation hole.
- A collection-expression element or spread element (`[this.a, .. this.items]`).
- A switch-expression arm, including its `when` clause (`1 when this.a > 0 => ...`).
- A `ref` or `out` argument, or a deconstruction target.
- A member of a class or a struct, in a method body, an expression body, an accessor, a constructor, a local function, a lambda, or a nested lambda.

### The check

The rule reports `this.X` when all of these hold:

- `this.X` binds to exactly one instance field, property, method, or event.
- Looking up the name `X` alone at that position finds the same member. For a method, it finds a method group that contains it.
- The code binds the same way with the name alone. The name keeps the member of `this.X`, and every expression around it, up to the enclosing statement or initializer, keeps its type, converted type, and symbol. A lambda or anonymous method is compared by type only, and an element of a collection initializer keeps its `Add` method.
- The code parses the same way without `this.`.
- Every removal the rule reports in the same statement or initializer holds together with the others, in binding and in parsing. There is no limit on how many removals one statement can have.

The last point matters because removals that are safe one at a time can change the code together. In `F(this.A < this.B, this.C > (d))`, removing `this.` from either `B` or `C` leaves two comparisons, but removing it from both turns the argument into a call to a generic method `A<B, C>(d)`. The rule then reports none of the removals in that statement.

### Positions the rule cannot re-bind

The rule skips an access in a position where it cannot bind the code without `this.`:

- A query clause after the first `from`.
- A `case ... when` clause in a `switch` statement.
- An exception filter.

## What the rule does not report

- A name that another symbol hides at that position: a parameter, a local, a lambda parameter, a local function, a range variable, a pattern variable, or `value` in a setter. In `public void Set(int count) => this.count = count;`, `this.count` is the field and `count` is the parameter.
- An inherited member that has the name of a primary constructor parameter of the type, such as `this.count` in `class Derived(int count) : Base`, where `Base` declares `count`. Without `this.`, the name still reaches the member, and the compiler warns that the member hides the parameter (CS9179). A member that the type declares itself is reported.
- `this.field` in a property or indexer accessor, including an expression-bodied property and a lambda or local function inside one. From C# 14, `field` in an accessor is the keyword for the backing field, so removing `this.` would change what the code means. The rule skips it under every language version. `this.@field` is reported, and the fix leaves `@field`, which always names the member.
- A removal that would parse differently. In `(this._map)(value)`, where `_map` is a delegate, `(_map)(value)` reads as a cast.
- An access with a comment or a preprocessor directive between `this` and the name, in the trivia of `this` or of the `.`. A comment or directive before `this` does not stop the rule.
- An access with a compile error.
- An access whose removal changes the binding of an enclosing expression, such as the type or symbol of a call that receives it.
- An access in a position listed under "Positions the rule cannot re-bind".
- `base.X`, `this[...]`, and `this?.X`.
- An extension method or extension property called through `this`, such as `this.Ext()`.
- Generated code.

## Configuration

Set the severity in an `.editorconfig` or globalconfig file:

```ini
dotnet_diagnostic.CCA0004.severity = warning
```

`ChilliCream.AnalyzerConfig.Libraries` sets CCA0004 to `warning` and turns [IDE0003] off. Use `none` to turn the rule off.

The code fix ships in `ChilliCream.Analyzers`. Fix All applies every diagnostic in one pass, because the removed spans never overlap and the removals reported in one statement or initializer were proven safe together.

## Related rules

- [IDE0003] reports the same `this.`, but runs only in the IDE, because it is not among the code-style analyzers that `EnforceCodeStyleInBuild` adds to a build. `ChilliCream.AnalyzerConfig.Libraries` turns it off in favor of CCA0004.
- [IDE0009] adds `this.` where it is missing. It is the opposite of CCA0004.
- The `dotnet_style_qualification_for_field`, `dotnet_style_qualification_for_property`, `dotnet_style_qualification_for_method`, and `dotnet_style_qualification_for_event` options do not affect CCA0004.
